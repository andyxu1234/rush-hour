# 06 · 测试、验收与发布

---

## 1. 测试分层

| 层 | 工具 | 覆盖对象 | 门禁 |
|---|---|---|---|
| L1 逻辑单测 | vitest | `packages/core` 全部（规则/求解/状态机/存档） | 覆盖率 **≥ 95%**（lines & branches），不达标 CI 失败 |
| L2 跨语言一致性 | vitest + Python | TS 求解器 vs Python 参考求解器，对 66 关逐一比对 | **66/66 必须一致**，不一致 CI 失败 |
| L3 关卡数据校验 | Python | `data/levels.json` 全部不变量 | 每关必过 `check_levels.py` |
| L4 渲染快照 | vitest + canvas mock | 空棋盘/满棋盘/选中态/动画中间态 | 快照变更必须人工确认 |
| L5 端到端（H5） | Playwright | 真实拖拽、通关、撤销、结算、选关、存档恢复 | 主流程用例全过 |
| L6 真机冒烟 | 人工 checklist | 小游戏真机表现 | 每阶段一次，上线前必做 |

> L2 是本项目**最重要的一道测试**。它保证"客户端算出的 par / 是否能解 / 提示是否正确"与离线生成时的权威结果完全一致——这是所有防作弊与星级判定的地基。

## 2. L1/L2 关键用例表

### 2.1 规则层（`moves.ts`）

| 用例 | 期望 |
|---|---|
| 横车前方有 2 空位 | `generateMoves` 产出 2 个候选，分别滑 1 格与 2 格 |
| 横车前方紧邻另一辆车 | 该方向 0 个候选 |
| 竖车同理 | 上下各自独立计算 |
| 车在边界贴边 | 越界方向 0 个候选 |
| 红车滑到 `(2,4)` | `isSolved() === true` |
| 红车滑到 `(2,3)` | `isSolved() === false` |

### 2.2 求解层（`solver.ts`）

| 用例 | 期望 |
|---|---|
| 已知 1 步关卡 | `minMoves === 1` |
| 已知 2 步关卡 | `minMoves === 2` |
| 不可解关卡（构造定理 2 违规盘面） | 返回"不可解"，不抛异常、不死循环 |
| `nextOptimalMove` 随机局面模糊测试（≥200 次） | 按建议走一步后，剩余最少步数恰减 1 |
| 状态数上限保护 | 病态盘面在达到上限时安全退出，不 OOM |

### 2.3 状态机（`game.ts`）

| 用例 | 期望 |
|---|---|
| 连续移动 5 次后撤销 5 次 | 回到初始局面，步数 0 |
| 撤销后重做 | 局面与撤销前完全一致 |
| 撤销 0 次局面上再撤销 | 无副作用，不报错 |
| 通关后再撤销 | 是否允许回退需明确定义（**决策：允许，但成绩一旦提交不可撤回**） |
| 步数 = `moves.length` | 任何时刻恒等 |

### 2.4 存档层（`levels.ts`）

| 用例 | 期望 |
|---|---|
| 通关 t01 后 | t02 解锁，t01 记录星级 |
| 注入空存档 | 仅 t01 解锁 |
| 存档 JSON 损坏 | 安全降级为全新存档，不崩 |
| 存档版本号不匹配 | 执行迁移或安全重置 |
| 双端合并（更优值取自两端） | `mergeProgress` 结果正确 |

### 2.5 防作弊（服务端）

| 用例 | 期望 |
|---|---|
| 合法完整通关序列 | `accepted: true` |
| 序列中有非法走子 | `rejectReason: 'illegal_move'` |
| 序列合法但未通关 | `rejectReason: 'not_solved'` |
| 少报步数（`clientMoves` 不符） | `rejectReason: 'steps_mismatch'` |
| 不存在的 levelId | `rejectReason: 'level_unknown'` |
| 同一成绩重复提交 | `already_better`，不降低已有成绩 |
| 超过每日提交上限 | `rate_limited` |

## 3. L3 关卡不变量（每关必须全部满足）

`tools/check_levels.py` 必须逐关断言：

| # | 不变量 | 违反后果 |
|---|---|---|
| I1 | 所有车在 6×6 棋盘内 | 渲染越界 |
| I2 | 车辆之间无重叠 | 状态非法 |
| I3 | 红车为 `H` + `len=2` + `row=2` | 玩法破坏 |
| I4 | 关卡**可解** | 玩家必然卡死（最严重） |
| I5 | `par.moves` 等于求解器结果 | 星级判定错误 |
| I6 | `par.cells` 等于 Dijkstra 结果 | 展示错误 |
| I7 | 定理 2 违规不成立（出口行右侧无横车） | 必然不可解 |
| I8 | `idlePieces ≤ 1`（无大面积纯装饰车） | 关卡显得"注水" |
| I9 | `rootMoves ≥ 2`（开局至少有 2 种选择） | 玩法退化 |
| I10 | 关卡 id 唯一 | 存档串关 |
| I11 | **`levels.json` 中不含 `solution` 字段** | 解答泄露 |
| I12 | 难度等级与 `par.moves` 区间一致 | 分级展示错误 |

## 4. L5 端到端用例（Playwright on H5）

| 用例 | 步骤 | 断言 |
|---|---|---|
| 首屏 | 打开页面 | canvas 存在，无 console error，1.5s 内可交互 |
| 完成教学首关 | 拖拽红车到出口 | 结算弹窗出现，显示 3 星 |
| 拖拽回弹 | 向非法方向拖 1/4 格后松手 | 车回到原位，步数不变 |
| 撤销 | 走 3 步后撤销 2 次 | HUD 步数 = 1 |
| 断点续玩 | 走到第 3 步刷新页面 | 恢复到第 3 步局面 |
| 解锁流程 | 完成 t01 | 选关页 t02 可点 |
| 提示 | 点提示 | 显示"下一辆该动的车"，且该建议确实是最优 |
| 存档损坏 | 手动写入非法 JSON 后刷新 | 安全重置为初始状态，不白屏 |
| 多机型适配 | 375×667 / 414×896 / 768×1024 | 棋盘居中不变形，无裁切 |

## 5. 性能预算

| 指标 | 目标 | 测量方式 |
|---|---|---|
| 冷启动到可交互 | ≤ 1.5 s（中端机） | 真机 + `app_launch` 埋点 |
| 渲染帧率 | 60 FPS（低端安卓 ≥ 45） | 开发者工具性能面板 + 真机 |
| 求解器 BFS（66 关内最难关） | ≤ 200 ms | 单测中断言耗时 |
| `nextOptimalMove`（提示响应） | ≤ 30 ms | 单测中断言耗时 |
| 主包体积 | ≤ 4 MB（目标 ≤ 1.1 MB） | 构建脚本自动断言 |
| 总包体积 | ≤ 30 MB | 构建脚本 |
| 单次存档写入 | ≤ 5 ms | 手动 profile |
| 内存占用 | ≤ 120 MB | 真机 |

## 6. 真机冒烟清单（每阶段一次）

- [ ] 冷启动无白屏，控制台无 error
- [ ] 画布铺满屏幕、不模糊、刘海屏不遮挡操作区
- [ ] 拖拽跟手，无延迟感，吸附准确
- [ ] 音效/震动按设置生效；静音后立即静音
- [ ] 切后台 → 回前台：动画与音频正常恢复，局面未丢
- [ ] 来电/通知打断后恢复正常
- [ ] 低电量模式、飞行模式下可正常游玩（离线）
- [ ] 连续通关 10 关无内存增长异常

### 白屏排查清单（高频问题）
1. 小游戏模板是否选对（头号原因）
2. 是否有 `eval` / `new Function` / 动态 `import`（小游戏禁用，会直接崩）
3. 是否误用了 `document` / `window` / `Image`（无 DOM 环境）
4. 首屏是否依赖网络资源（弱网会黑屏闪烁）
5. `game.json` 与构建产物的目录结构是否匹配
6. WebGL 后端选择：真机与开发者工具可能不一致，2D canvas 优先

## 7. 提审发布 Checklist（逐项打勾，缺一不提审）

**功能**
- [ ] 66 关全部可通关，无死局（`levels:check` 全绿）
- [ ] 教学引导可跳过且不重复出现
- [ ] 断点续玩、存档、清档均正常
- [ ] 每日挑战跨天正确换题（北京时间）
- [ ] 排行榜数据经服务端重放校验

**合规**
- [ ] 游戏内**有隐私政策入口**且可正常打开（高频驳回项）
- [ ] 展示适龄提示
- [ ] **无强制分享**（无"分享才能解锁/复活"）
- [ ] 插屏广告不在关卡进行中弹出
- [ ] 激励视频有明确的奖励预告，且有失败兜底
- [ ] 类目为「游戏 → 休闲游戏」
- [ ] 软著或电子版权认证 + 游戏自审自查报告已上传
- [ ] 无内购入口（个人主体不允许）

**技术**
- [ ] 主包 ≤ 4 MB、总包 ≤ 30 MB（构建脚本已断言）
- [ ] 请求域名已加入后台白名单（自建后端）；云开发无需
- [ ] 生产构建无 `console.log` 泄漏敏感信息
- [ ] 网络失败全部有降级，不影响单机游玩
- [ ] 埋点事件名与 `04` §7 一致
- [ ] 保留上一个可用体验版，具备回滚方案

**提审材料**
- [ ] 完整体验路径说明（选关 → 通关 → 结算）
- [ ] 游戏截图与录屏
- [ ] 玩法介绍文案（说明"这不是简单点击，是滑块解谜"——避免被判"非游戏"）

## 8. 上线后监控口径

| 指标 | 健康值 | 异常动作 |
|---|---|---|
| 关卡漏斗 `win/start` | ≥ 60%（入门关 ≥ 90%） | < 40% 的关卡进入难度再校准 |
| 次日留存 | 参考休闲解谜品类 | 低于预期则强化每日挑战与连续签到 |
| 提交驳回率 | < 1% | 上升说明客户端有 bug |
| 广告填充失败率 | < 15% | 高于则调低广告依赖，提升免费提示配额 |
| 崩溃率 | < 0.5% 会话 | 高于则热修 |
| 平均每关步数 vs par | 1.2–2.0 倍 | 偏高说明引导不足，偏低说明太简单 |
