# 01 · 玩法与游戏设计规格

本篇是**规则的法律条文**。实现与关卡设计中的任何分歧，以本篇为准。

---

## 1. 精确规则

### 1.1 棋盘

- 尺寸 **6 列 × 6 行**，坐标 `(row, col)`，均 0-indexed，`row` 向下增长。
- 出口位于 **第 2 行（`EXIT_ROW = 2`）的右边缘**，宽 1 格（与 6×6 经典华容道一致）。
- 棋盘外不可停留；车辆任何时刻必须完整落在棋盘内。

### 1.2 车辆

| 属性 | 取值 | 说明 |
|---|---|---|
| `dir` | `"H"` / `"V"` | 横车 / 竖车 |
| `len` | `2` / `3` | 占 2 格或 3 格 |
| `kind` | `"red"` / `"car"` | 红车唯一且恒为 `H` + `len=2` |
| 锚点 | `(r, c)` | 该车所占**最上一格、最左一格**的坐标 |

红车初始必须位于 `row = 2`（水平方向与出口对齐）。

### 1.3 移动

- 横向车只能左右移动，竖向车只能上下移动。**不能转弯、不能旋转、不能换道。**
- 一次移动可滑动 **1 格或连续多格**，但路径上的目标格必须全部为空，不可跨越任何车辆。
- **一次"移动"的定义：一辆车沿一个方向滑动一次。** 无论滑了 1 格还是 5 格，都算 **1 步**。
  - 这是全项目的**默认计步口径**（决策 D4）。
  - 另有一个副指标 `cellSteps`（所有移动的格数总和），仅用于展示"你共挪动了 N 格"，不作为星级依据。
- 红车驶出：红车锚点到达 `(2, 4)`（即占据 `(2,4)` 与 `(2,5)`）即判定通关，随后播放驶出动画。

> **实现注意**：一次拖动如果能让车滑动 k 格，必须生成 **k 个不同的候选状态**（各计 1 步），而不是只生成"滑到底"。解法搜索与"是否还能达到 par"的判定都依赖这一点。

### 1.4 出界与非法

- 拖拽方向非法（前方无空位）→ 回弹动画 + 轻微抖动 + 短促音效，**不计步**。
- 拖拽距离超过可用距离 → 吸附到最远处，**计 1 步**。
- 拖拽距离不足以越过一个格子的 50% 阈值 → 回弹，**不计步**。

## 2. 两条定理（实现与关卡设计的地基）

### 定理 1（可逆性）——不存在"死局"，因此可以无限重试

**命题**：若状态 A 可通过一次移动到达状态 B，则 B 也可通过一次移动回到 A。

**证明**：一次移动是某辆车沿自身轴向滑动 k 格，路径格全空。反向滑动 k 格时，车辆原占据的格子此刻必然为空，故反向滑动合法。∎

**推论（对产品的直接影响）**：
1. 状态图是**无向图**；任何从初始状态可达的局面，都仍然可解。玩家**永远不会把局面走死**。
2. 因此**不需要**"无法完成，是否重开"的提示逻辑，也不需要"撤销需要付费/看广告"这类设计——撤销应当免费且无限（决策：撤销免费、无次数限制）。
3. 求解器实现可以**从目标状态集合反向 BFS**，与正向 BFS 共用同一套邻接关系（本项目参考实现即如此）。

### 定理 2（出口行右侧横车 —— 必然死局）

**命题**：若存在一辆横向车位于第 2 行，且其最左格列号 `c > red_c`（即完全在红车右侧），则该关卡**必然不可解**。

**证明**：横向车恒在第 2 行内活动，永远不会离开该行。同一行内两辆车无法交换左右次序（只能沿行滑动，不能跨越）。故该横车在全部可达状态中始终位于红车右侧。通关要求红车占据 `(2,4)`、`(2,5)`；此时该横车必须位于第 5 列之后，越界，矛盾。∎

**用途**：
- 关卡生成器用它做**前置剪枝**，省掉大量无效 BFS（`tools/rush_hour.py: random_layout()`）。
- 关卡编辑器用它做**实时校验**，保存前直接报错。
- 该定理已在参考实现中做了随机反例自检（`verify_prune_rule()`，400 次随机构造，反例数必须为 0）。

## 3. 计分与星级

| 星级 | 条件 |
|---|---|
| ★★★ | `moves == par.moves`（达成理论最少步数） |
| ★★ | `moves <= par.moves + 2` |
| ★ | 完成即得 |

- `par.moves` 由求解器 BFS 离线计算并写入关卡数据，**客户端不得自行推算 par 后写入存档**（防作弊，见 `04`）。
- 成绩申诉：客户端提交完整走子序列，服务端重放；重放结果与客户端上报不一致 → 该次成绩作废并记录风控事件。

## 4. 难度分级

主指标＝`par.moves`；副指标只用于选关页的"思考空间"标签，不参与分级公式。

| 等级 | `par.moves` | 设计意图 |
|---|---|---|
| `starter` 入门 | 1 – 3 | 教会拖拽、认识竖车让路 |
| `easy` 简单 | 4 – 7 | 建立"先让路再走"的直觉 |
| `medium` 中等 | 8 – 12 | 需要规划 2~3 步的先后顺序 |
| `hard` 困难 | 13 – 18 | 需要试错与回溯 |
| `expert` 专家 | 19 + | 长链推理，多数玩家需要多次尝试 |

副指标（存于 `metrics`，用于展示与调优）：

- `reachableStates`：可达状态总数 —— 表征"思考空间"大小。
- `optimalPaths`：最少步数解法条数 —— 为 1 表示唯一解（更难），数值大表示冗余多（更宽容）。
- `idlePieces`：在整个可达状态空间中从未移动过的车数（纯装饰，须 ≤ 1）。
- `maxBranching`：局面最大可选移动数。

## 6. 屏幕清单与交互规范

### 6.1 屏幕清单

| 屏幕 | 元素 | 状态/边界 |
|---|---|---|
| **启动加载** | 进度条、logo | 必须在 1.5s 内可交互（首屏不拉网络资源） |
| **主菜单** | 继续上局、开始闯关、每日挑战、排行榜、设置、隐私政策入口 | 首次进入走强制新手引导 |
| **选关页** | 关卡格子（星级、锁定态）、分页/章节、当前进度 | 未解锁关卡灰显不可点；已通关可重玩刷星 |
| **游戏页** | 棋盘、红车、出口箭头、步数、par 步数、撤销、重开、提示按钮 | 见 6.2 |
| **结算弹窗** | 步数、星级动画、`par` 对比（"比最少步数多 3 步"）、重玩/下一关/分享 | 达 par 时特殊文案与特效 |
| **提示弹窗** | 提示内容（高亮下一辆该动的车 + 方向箭头）、"看视频再给一次" | 见 6.4 |
| **排行榜** | 好友榜（开放数据域）、全球榜、我的排名 | 未登录时展示本地最好成绩 |
| **设置** | 音效、震动、计步显示口径（步/格）、语言、清除本地存档 | 清档需二次确认 |
| **隐私政策** | 静态文本页 | **合规必需**，提审硬性要求（见 `04` 合规章节） |

### 6.2 游戏页交互

- **主交互：拖拽**。手指按住某辆车 → 该车沿自身轴向跟手移动 → 松手吸附到最近合法格。
- **辅助交互：点击**。点车选中（高亮）→ 点目标格移动。用于单手/精准操作与无障碍。
- 拖拽时**实时显示可滑动范围**：在车辆前后绘制半透明可占位虚影，超出范围的车身部分变暗。
- 不可移动的车**不做**禁用态（避免挫败感），但拖拽时会给出"顶住感"（微阻尼 + 回弹）。
- 松手后 60ms 内完成吸附插值；非法方向播放 x 轴抖动（约 120ms，振幅 4px）。

### 6.3 手感参数（建议初值，真机微调）

| 参数 | 初值 | 说明 |
|---|---|---|
| 吸附判定阈值 | 移动距离 ≥ 0.5 格 | 低于则回弹 |
| 滑动动画时长 | 120 ms / 每格，上限 240 ms | 缓动 `easeOutCubic` |
| 非法回弹时长 | 160 ms | 带一次轻微过冲 |
| 过关动画 | 红车加速驶出 400 ms + 白光闪 120 ms | 可跳过（点击任意处） |
| 长按提示 | 800 ms 长按车 → 显示该车可移动方向 | 新手教学用 |

### 6.4 提示与广告点位

- 每关免费提示 **1 次**；之后需看激励视频（30s）再得 1 次。
- 提示粒度＝**只揭示下一辆车与方向**，不直接展示完整解法（保留思考乐趣，也利于广告复投）。
- 插屏广告：每完成 **3 关**触发一次，且**不得**在关卡进行中弹出，不得遮挡操作区。
- **合规红线**：禁止"分享给好友才能解锁下一关"这类强制分享（提审高频驳回项）。

## 7. 美术规格

- 设计分辨率 **375 × 667**（逻辑像素），渲染时按 `devicePixelRatio` 缩放 canvas，上限 3×。
- 棋盘：留白 5% 边距，8px 圆角格子，格线 `#E9ECEF`，棋盘底色 `#F8F9FA`。
- 车辆：圆角矩形 + 顶部高光 + 底部投影；车灯两个小圆；长度 3 的车中部加深色车窗。
- 色板（建议）：

| 用途 | 色值 |
|---|---|
| 背景 | `#F4F6F8` |
| 棋盘 | `#FFFFFF` |
| 格线 | `#E9ECEF` |
| 红车 | `#E03131`（描边 `#B02525`） |
| 敌方车（冷色组） | `#4C6EF5` / `#15AABF` / `#7048E8` |
| 敌方车（暖色组） | `#F59F00` / `#F76707` / `#37B24D` |
| 出口箭头 | `#12B886` |
| 主文字 | `#212529` |
| 次文字 | `#868E96` |

- 同一关内**不同车辆必须颜色互不相同**（同色车会让玩家误以为可以互换），生成器分配颜色时按 `piece.id` 哈希取色并去重。
- 所有美术资源优先用**代码绘制**（Canvas 矢量）而非位图：省包体、任意缩放不失真、无需图集。仅在需要"精致感"时才引入小尺寸位图。

## 8. 音效清单

| 事件 | 音效 | 备注 |
|---|---|---|
| 车辆吸附成功 | 短促"咔" | 0.08s |
| 非法移动 | 低频"咚" | 0.1s，音量降低 |
| 撤销 | "咻"上行 | 0.1s |
| 过关 | 上行三音 + 柔和和弦 | 1.2s，达 par 时附加特殊音 |
| 点按 UI | 极轻 click | 0.03s，可关 |
| 背景音乐 | 8-bit 轻量循环（≤30s） | 默认开，可关；文件放分包 |

音频总预算 **≤ 400 KB**（走分包，见 `02` 包体预算）。

## 9. 新手引导

前 3 关即教学关，用**情境化遮罩 + 文案**而非独立教程页：

1. **t01（1 步）**：只高亮红车，"向右拖动红车开出出口"。
2. **t02（2 步）**：第一辆挡路竖车，文案"竖车只能上下移动，先把它挪开"。
3. **t03（4 步）**：多辆挡路车，文案"一次只能动一辆车，想好顺序"。

引导状态存本地，跳过引导的入口放设置页。
