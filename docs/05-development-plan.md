## P1 · 玩法内核（DoD：与 Python 求解器逐关一致）

**目标**：`packages/core` 成为纯函数式的规则实现，可在 Node 下完整测试。**这一阶段不碰任何渲染。**

### 前置：P0 完成

### 任务
| 编号 | 任务 | 验收点 |
|---|---|---|
| P1-1 | `model.ts`：`Piece`/`Level`/`State` 类型 + `validateLevel()` 不变量（边界、重叠、红车约束） | 对 66 关全部 `validateLevel` 通过；构造非法关卡必须抛错 |
| P1-2 | `moves.ts`：`generateMoves(state)` —— **必须是"每个可达格数一个候选状态"**，各计 1 步 | 与 `01-game-design.md` §1.3 完全一致，含"滑 2 格"与"滑 5 格" |
| P1-3 | `solver.ts`：BFS 求 `minMoves`（多源反向 BFS 求 `distGoal`）+ 最优解条数 DP | 与 `tools/rush_hour.py` 对 66 关结果**逐关完全一致** |
| P1-4 | `solver.ts`：Dijkstra 求最少 `cellSteps` | 同上，与 Python 一致 |
| P1-5 | `solver.ts`：`nextOptimalMove(state)` —— 从**任意中间局面**给出最优下一步 | 随机局面测试：按其建议走，剩余步数恰减 1 |
| P1-6 | `game.ts`：对局状态机（`moves[]` 为唯一事实来源）+ 撤销/重做 + 星级判定 | 撤销后重做，状态与预期完全一致 |
| P1-7 | `levels.ts`：关卡包加载、解锁规则（前一关 1 星才解锁下一关）、进度读写（注入 Storage） | 注入内存 Storage 单测全部通过 |
| P1-8 | **交叉校验脚本**：读 `data/levels.verify.json`，用 TS 实现复算每关 `minMoves`，与文件中的值比对 | 66/66 一致；不一致则 CI 失败 |

### DoD
- [ ] `packages/core` 单测覆盖率 ≥ 95%（lines & branches）
- [ ] P1-8 交叉校验脚本接入 CI，66 关全绿
- [ ] `packages/core` 中零 `window`/`wx`/`document` 引用（lint 通过）
- [ ] `nextOptimalMove` 有随机模糊测试（≥ 200 个随机局面）

### 风险
状态表示若用嵌套对象会导致 BFS 慢 100 倍。**必须**用平坦元组/整型编码（Python 参考实现用 `tuple[(r,c)]`，TS 用 `Int8Array` 或字符串 key）。这是性能红线，不要"先跑通再优化"。

## P2 · 渲染与交互（DoD：真机通 10 关，手感达标）

**目标**：成为一个真正能玩的游戏。

### 前置：P1 完成

### 任务
| 编号 | 任务 | 验收点 |
|---|---|---|
| P2-1 | `theme.ts`：色板/尺寸常量，严格对应 `01-game-design.md` §7 | 改色值只需改此文件 |
| P2-2 | `canvas2d.ts`：绘制棋盘、格线、出口箭头、车辆（圆角+高光+车灯+车窗） | 截图与设计稿目视一致；不同车颜色互不相同 |
| P2-3 | `anim.ts`：缓动函数 + 补间队列（吸附/回弹/抖动/过关） | 动画期间输入不丢失、不重复计步 |
| P2-4 | `input.ts`：拖拽手势 → 语义事件（`dragStart/dragMove/dragEnd`），含 0.5 格吸附阈值与非法方向判定 | 拖到一半松手必须回弹且**不计步** |
| P2-5 | 拖拽可视化：可滑动范围的半透明虚影 + 越界变暗 | 真机目视确认 |
| P2-6 | 点击交互：点车选中 → 点目标格移动（与拖拽共存不冲突） | 两种操作混用无 bug |
| P2-7 | 游戏页 HUD：步数、par 步数、撤销、重开、提示按钮 | 步数与实际移动严格同步 |
| P2-8 | 音频接入（Platform.audio）：吸附/非法/撤销/过关 | 静音开关立即生效；切后台自动暂停 |
| P2-9 | 过关流程：红车驶出动画 → 结算弹窗（星级、与 par 对比） | 达 par 时展示专属文案与特效 |
| P2-10 | 自适应：多机型（窄屏/刘海屏/平板）与 60 FPS | 见 `06` 性能预算 |

### DoD
- [ ] **真机**连续通关 10 关无卡顿、无错位、无计步错误
- [ ] 帧率稳定 60 FPS（低端安卓 ≥ 45 FPS）
- [ ] 动画中断、快速连点、多指触摸等边界情况不崩
- [ ] 关掉声音/震动后无残留副作用

### 风险
手感是主观项且最容易返工。对策：P2-2 完成后立刻做**真机手感评审**，参数集中在 `theme.ts`/`anim.ts`，调参不动逻辑。

## 执行纪律（给 coding agent）

1. **不要跳阶段**。P1 未通过交叉校验就去做 P2，会在渲染阶段发现规则错了，返工成本极高。
2. **par 永远由求解器计算**。任何人工填写的 `par.moves` 都视为 bug。
3. **不修改已冻结的接口**（`02` §4 的 `Platform`、`04` 的 API 契约）。要改先改文档并说明理由。
4. **每完成一个任务编号，跑一次对应测试**，并在 commit message 里带上编号。
5. **性能红线**：BFS 状态编码必须平坦化；提示响应 < 30ms；主包 ≤ 4MB。
6. **每次提审前**，把 `06-testing-acceptance.md` 的发布 checklist 打印出来逐项确认。
